## 结论

本次审计时项目维护“原 Software Manager 自动加载 → 客户端退出前全量归档 → 退出未知文件提示静默保留”的内置功能。自定义业务回调不再是受支持的接口；源码和新发布 JAR 均不含该接口及示例类。后续会话过期场景的策略扩展见 [验证记录](验证记录.md) 的 2026-11-07 章节。

本次删除旧产物后，使用 Lucanet 自带 JDK 21.0.11+10 从当前源码重新构建并完成行为、真实库、安装/卸载及 Maven 产物回归。没有通过删除测试、许可证或运行依赖来缩减项目。

## 修复及防止重复堆积

- **安装参数匹配修复**：原安装器以字符串前缀匹配删除 Agent 行，可能误改同前缀的 `.jar.other` 或带独立参数的条目。现改为整行匹配，状态检查也采用整行判断。测试已覆盖类似前缀、其他 Agent、重复安装及卸载后原配置逐字节恢复。
- `build.ps1` 在 `finally` 中清理本次编译目录，先验证目录位于 `build` 内且无目录联接。
- `package.ps1` 改为按白名单直接写 ZIP，临时 ZIP 在成功/失败后清理，不再生成整份 `release-*` 目录。
- 新打包路径显式加载 `System.IO.Compression` 与 `System.IO.Compression.FileSystem`，解决 Windows PowerShell 5.1 下 `ZipArchiveMode` 类型未加载的问题。

## 保留文件的依据

- 6 个运行类均参与 Agent 加载、原生链传递、内存转换、文件归档或日志记录。
- `tools/AssembleAgent.java` 是离线构建必需；两个真实类测试工具用于验证专有接口，不能当作历史示例删除。
- 真实对话框测试仍反射使用蓝科自己的 `ApplicationStateListener`，用于到达真实退出阶段；这是测试依赖，不是对外回调接口。
- 安装器仍含旧版 `UserExitAction.class` 的字符串检查，用来拒绝误装旧回调包；该字符串不是可执行接口。
- PowerShell 和 Maven 构建入口均保留：前者支持本机离线组装，后者支持标准 IDE/Maven；均使用 Lucanet `.jdk` 的最高完整版本。
- ASM 私有包及其 BSD 许可证是 Agent 的运行依赖，保留在 JAR/交付包中。
