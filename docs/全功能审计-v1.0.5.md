# 全功能审计与 Lombok 撤回

审计日期：2026-11-20。交付版本按用户要求保持 **v1.0.5**，未改动版本号。

本轮审阅全部功能的关键实现及边界，并重新执行 Java、真实 Lucanet 组件、Windows 管理器和交付包测试。修复了更新包解压长度校验、热更新加载器保留和 CRLF 编辑三个问题。在所列范围内未发现尚未修复的高危问题；测试范围不包括 Lucanet 服务端、真实业务数据库及所有版本组合。

## Lombok 撤回结果

- 删除 Lombok 专用处理器装载、编译选项注入及生成成员分析实现；`DynamicCompiler` 不再是字节码转换目标。
- 编辑器的所有 javac 分析恢复 `-proc:none`，不会实例化或执行已加载依赖中的注解处理器。删除为 Lombok 分析临时补分号、处理失败诊断等专用逻辑。
- 交付 JAR 不包含 `JavaLombok`、`LombokCompiler`、`LombokLibrary` 及 Lombok 依赖。
- 保留独立的通用 `@` 补全：只提示注解类型、按需导包、支持包名前缀；注解参数内使用普通表达式补全。JDK、同脚本类型及已加载额外库仍参与解析。
- 未删除用户在 Administrator 上传的依赖，也未改动用户注解源码、原生编译配置或真实安装目录。

验证使用两个相互独立的检查：

1. **编辑器处理器隔离**：生成一个通过服务文件注册的测试处理器。普通 javac 的阳性对照确实执行该处理器；相同依赖加入编辑器后，注解补全、诊断及方法分析均不触发其构造或执行。移除依赖后注解候选随之消失。JDK 21 与 17 均通过。
2. **原生编译器对照**：分别在不加载增强和加载增强的隔离 JVM 中，调用真实 `DynamicCompiler.compile`。比对有效源码的每个类字节码 SHA-256，以及无效源码的错误类型、文件、行列、位置和消息。默认选项与显式 `-proc:none` 均一致；同时检查原生编译类不会被转换。

因此 Lombok 能否生成方法、如何处理其编译配置，由 Lucanet 原生流程决定。编辑器不再识别尚未编译的 Lombok 生成成员，可能显示缺失方法诊断；README 已明确这一边界。

## 发现并修复

| 级别 | 问题及复现 | 修复 | 验证 |
| --- | --- | --- | --- |
| P2 | 更新器只累计 ZIP 中声明的未压缩长度。将条目声明长度改为 1，实际内容仍为 7 字节，旧实现仍接受，实际解压体积上限可被畸形元数据绕过。 | 解压时逐块累计实际字节数，要求单文件长度与声明一致，并限制实际总量；失败后清理本次新建的解压目录。保留下载来源、SHA-256、路径和完整包检查。 | 伪造短长度／长长度均拒绝，失败目录被清理，合法的新旧目录结构仍通过。见 `audit-zip-before.txt`、`audit-zip-after.txt`。 |
| P2 | `AgentRuntime` 静态登记列表强引用每个热更新加载器。即使事务结束、旧调用释放，旧模块仍不可回收，长期反复更新会累积资源。 | 改为弱引用登记并清理失效项。活动模块、回滚引用和在途调用自然保有其加载器，不提前关闭仍可能延迟加载类或资源的旧加载器。 | 双 JVM 真实切换、准备／提交失败回滚及后续启动通过；更新后保留的旧模块仍能加载新类、读取资源、完成调用，释放引用后可被 GC 回收。 |
| P2 | CRLF 源码合并行留下单独的 `\r`；末行复制／移动、多行模板及空行缩进会混用换行符。 | 将行内容与 CRLF/LF 分隔符分开处理，删除／合并完整分隔符，新增文本沿用文档换行格式，缩进保留原分隔符。 | LF/CRLF 的复制、删除、上下移动、合并、新行、缩进及模板回归通过；两套真实原生编辑器验证合并／移动及一次撤销精确恢复 CRLF 源码。 |

ZIP 问题需要更新包本身具有异常内容；下载器仍限定项目发布地址并验证 SHA-256。本轮没有发现任意外部地址可直接绕过来源校验下载执行的路径。

主要修复文件：`gui/update-service.cs`、`AgentRuntime.java`、`JavaEditing.java`。Lombok 撤回涉及 `NativeTransformer.java`、`JavaIntelligence.java`、`JavaEditorAssist.java` 及相关专用文件删除。

## 使用边界与安装

本次应正常关闭客户端及 Software Manager，完整解压运行包后打开 `lucanet-client-enhancement/enhancement.exe` 点击安装，再从原 Software Manager 启动。这样能同时撤除旧 JVM 中的 Lombok 注册，并加载修复后的稳定启动桥；仅切换业务模块无法替换已经驻留的启动桥。

旧源码窗口及正在执行的旧模块调用会继续持有其加载器，直到窗口／调用结束。这是保留未保存草稿和完成在途调用所需；本次修复去除了登记列表造成的永久保留，未声称所有原生对象都能立即释放。未执行长时间负载与堆占用测量。

完整源码仍保存在原生 Class 节点的扩展属性中。使用这类节点的客户端需要相应增强读取源码；卸载、服务端重新编译和定时执行的适用范围仍按 README 中的说明处理。本轮未扩大或改变原生登录、权限、业务校验、执行锁及服务端行为。

生成菜单是已实现功能范围内的 IDEA 风格交互，不包含 IDEA 的全部生成器、重构与静态检查。真实 Administrator 上传、业务库执行和其他 Lucanet/JDK 组合仍需在对应环境验收。
