# 验证记录

日期：2026-11-05 起（Asia/Shanghai）。当前版本按用户要求统一为 v1.0.0，内置退出静默处理与原入口自动加载。下文早期的版本比较为当时测试记录。

## 本机真实类依据

只读核对并在独立 JVM 中验证：

- Software Manager `program-15.3.0-swm-fd4676f8.jar` 的 `ProgramLaunchConfiguration.toString(boolean, boolean)`。
- 客户端 `ln.application-17.15.3-lnsuite-10010a9a.jar` 的 `Application.stop()`。
- `lisa-6.8.0-lnsuite-f2d81fa7.jar` 的 `UnknownFileDialogCreator.a(XWindow, UIContext, String)`。
- `TempDirManager` 退出检查的结果分支：动作值 3 表示保留文件并返回；不是删除。

实际转换只发生在内存，不写回专有 JAR。Agent 通过 bootstrap 可见的私有包桥接，使用 Instrumentation 为 named modules 增加必要的读取/导出关系。

4. `test-real-lifecycle.ps1` 使用真实 `Application.stop` 验证文件在组件 prepareStop 前已归档，内部重启仍生效。
5. `test-native-integration.ps1` 使用真实 Software Manager named modules 解析/序列化配置，验证 Agent 参数传递；调用真实 UnknownFileDialogCreator 方法在真实 PREPARE_STOP 阶段返回 KEEP，在 headless JVM 中没有创建界面。

## 本机安装与桌面核验

已安装到 `D:\Soft\LucaNet\.client-enhancement\client-enhancement.jar`，为 `.2503+15` 和 `.2604+15` 中的 Software Manager/KickStart 原生配置添加了本增强。原配置备份在 `.client-enhancement/backups`。

通过 computer-use 打开原 `LucaNetSoftwareManager.exe`，从其界面启动一个已配置的 Financial Client。原生链日志中观察到 KickStart 的 `PROPAGATED` 与客户端的 `AGENT_ACTIVE`、`TRANSFORMED: ln/application/Application`。客户端正常显示业务主页，无额外增强启动器。

随后正常关闭此次客户端。蓝科原生的账户锁定确认仍然出现，自动化未代选账户操作；之后观察到客户端窗口已退出，日志记录 `EXIT_ARCHIVE_BEGIN`、`ARCHIVE_SUMMARY: moved=0, failed=0`、`EXIT_ARCHIVE_FINISHED`。此次桌面临时目录为空，因此“有未知文件时不弹提示”由非空/失败替身测试及真实对话框 headless 测试提供证据，不能把这次桌面退出描述成含文件场景的实测。

## 维护边界

- 只在 Financial Client 的 PREPARE_STOP/STOPPING/DISPOSING 阶段静默处理该未知文件对话框，其他业务提示保留。
- 归档失败或后续产生的剩余文件保留原处。全部普通临时文件在退出入口处理，符号链接/目录联接不跟随。
- Software Manager 升级生成新的版本目录/配置后需要重新安装并验证内部方法签名。未知版本转换失败会记录，不能保证静默功能仍生效。
- 强杀、崩溃和断电不保证执行；卸载只去掉本增强的启动参数，备份/归档不删除。

## 2026-11-06：自动刷新区域缩放错位修复

- 原实现使用流式容器及各控件不同的上边距，高 DPI 下数字输入框可能错位。改为固定一行的 `TableLayoutPanel`，控件按同一行垂直居中，行高按实际控件高度自适应。
- 父布局与内容区显式使用 100% 宽度列，修复缩窄窗口后仍保留旧宽度、导致右侧“秒”被父容器裁切的问题。
- `test-gui-window.ps1` 增加 100%、125%、150%、175%、200% 的实际控件/字体缩放模拟，每个比例分别验证默认窗口、缩窄窗口、300 秒数值和关闭自动刷新状态。断言覆盖控件同一行、中心线、输入框完整高度、间距和所有父容器的可见边界。
- 离屏图片核对了 100% 和 175% 布局，修复后复选框、数字框和“秒”均在同一行完整显示。模拟测试不等同于逐一修改真实 Windows 显示设置。
- 原有刷新持久化、静默轮询、旧请求失效、瞬时错误恢复与管理员交接隔离测试仍通过。此次只调整 GUI 布局与测试，不修改 Java 增强或客户安装配置。
