**`.var` 使用方式**

在可声明局部变量的代码块中输入 `expression.var`，按 **Tab**，也可以从补全列表选择 `var`。例如：

```java
java.util.List.of("a", "b").var
// 展开为：
var value = java.util.List.of("a", "b");
```

变量名会自动避开已有变量、后续局部声明和表达式引用的标识符，包括继承字段；选中生成的名称，便于直接改名。已有分号不会重复，一次 Ctrl+Z 撤销整个展开。不对 `void` 调用、单独的 `null`、单语句 if 分支或 switch 箭头表达式提供不可编译的局部声明。模板采用 JDK 17/21 支持的 `var`；已验证它能写入原生方法体并经原生编译器编译。

**用户特别提出的审查范围**

- 接口、接口实现、抽象类、继承、类类型参数、Record、枚举、注解类型、非原生包名等不能由原生部件完整表达的定义仍有具体红色说明和额外应用程序库指引。普通类的方法泛型、合法泛型构造方法与方法内 `var` 不误判为类级泛型限制。
- 兼容普通类转成增强专用类型时清理过期可编辑原生部件；改回普通类时可重新同步。增强专用类的原生占位结构被修改时保留增强源码，提示人工合并。
- 原生方法体、字段值、导入、新增/删除方法，经原生保存及增强端重载后可见；未保存增强草稿与原生新版本冲突时保留草稿并拒绝覆盖。
- 保留类/字段/方法声明注释。已删除或无法唯一匹配成员的注释放在类末尾；语法不完整时，无法定位的旧注释放到文件开头并显示提示。此时不保证原注释位置完全不变。原生明确替换或删除的方法体采用最新内容，不恢复已删除的旧业务代码。
- 增强源码窗口隐藏原生分隔注释和精确匹配的 `CallStack` 包装；原生源码页仍即时生成其包装。手写 `try/finally`、普通注释、文本块、字符串中的运算符、空行与相对缩进均经过回归。重复保存不叠加包装，格式化可重复执行。
- 自定义类型开关仍默认关闭。关闭入口或切换增强模块后，既有草稿保存能力及已保存源码的编译行为保留。
